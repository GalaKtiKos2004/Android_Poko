# PokeVault — финальный проект

**ФИО:** Ковтун Кирилл
**Группа:** _Б9123-09.03ю03 пикд(2)_

Персональный offline-first «покедекс» поверх [PokeAPI](https://pokeapi.co/) (без ключа).
API — источник контента (список и детали покемонов), а ценность приложения — в локальной модели:
профили, коллекции, статусы, заметки, история, сохранённые фильтры, политика актуальности кэша и фоновая синхронизация.

## Что добавлено в финальной работе

| Было (ДЗ 6) | Стало |
|---|---|
| Список + деталка из API, избранное | Локальные **профили**, у каждого — свои коллекции, статусы, заметки, история, фильтры и настройки |
| Room как кэш/избранное | Room — единый источник истины для UI; 7 таблиц со связями и каскадным удалением |
| Ручной refresh | **TTL-политика** актуальности, офлайн-предзагрузка и **периодическая синхронизация** через WorkManager |
| Flow для поиска | Экран собирается из 7+ независимых потоков (ввод, фильтры, профиль, Room, удалённый поиск, сеть, действия пользователя) |

### Хранение данных (Room)

| Таблица | Что хранит | Связи |
|---|---|---|
| `profiles` | локальные профили (имя уникально) | — |
| `collections` | пользовательские коллекции (название, описание) | FK → profiles, CASCADE; имя уникально в рамках профиля |
| `collection_pokemon` | состав коллекции + заметка к покемону внутри коллекции | many-to-many, FK → collections, CASCADE |
| `user_pokemon` | статус «Хочу / Поймал» и личная заметка | FK → profiles, CASCADE |
| `history` | история просмотров: одна строка на покемона, время и счётчик | FK → profiles, CASCADE |
| `filter_presets` | сохранённые фильтры (запрос, тип, статус, сортировка) | FK → profiles, CASCADE |
| `pokemon` | кэш контента API, метки `listUpdatedAt` / `detailUpdatedAt` для TTL и `catalogIndex` — позиция в серверном списке | не связан с пользовательскими таблицами, поэтому очистка кэша их не задевает |
| `pokemon_types` | связь покемон ↔ тип для фильтра | FK → pokemon, CASCADE |
| `type_sync` | когда список покемонов типа скачивался в последний раз (TTL) | — |

**DataStore** хранит только настройки и метаданные синхронизации: активный профиль, TTL кэша, фоновая синхронизация,
«только Wi-Fi», объём предзагрузки, общее число покемонов на сервере, время последней полной синхронизации
и результат последней попытки; плюс настройки профиля (тема, сортировка по умолчанию, запись истории) с ключами `p{id}_…`.

### Новые сценарии

1. **Локальные профили (крупный).** Создание / выбор / удаление профиля. Активный профиль хранится в DataStore и
   восстанавливается после перезапуска. Все личные данные и настройки разделены; при переключении профиля
   все экраны перестраиваются через `flatMapLatest`, меняется даже тема. Удаление профиля каскадно удаляет его данные.
2. **Пользовательские коллекции (крупный, новая сущность и связь).** Создание, переименование, удаление коллекций
   с валидацией имени; добавление покемона из деталки (в том числе «создать и добавить»), без дублей;
   экран коллекции со своими заметками к каждому покемону. Обложка и счётчик — из SQL-запроса.
3. **Статусы и заметки.** «Хочу / Поймал» + личная заметка на деталке. Статусы влияют на список (бейджи и фильтр
   через `LEFT JOIN` в запросе Room) и на статистику профиля в настройках.
4. **Сохранённые фильтры.** Текущий запрос + тип + статус + сортировка сохраняются под именем и применяются одним
   нажатием; управление (удаление) прямо на экране списка.
5. **Офлайн-режим и актуальность данных.** TTL (1/6/24/72 ч), кнопка «Скачать сейчас» для первых 151/251/386
   покемонов с прогрессом, периодическая синхронизация, очистка кэша с сохранением всего, что нужно пользователю.
6. **История / recent.** Последние просмотры с количеством просмотров, удаление записи, очистка; запись можно
   отключить в настройках профиля («инкогнито»).

### Как устроен offline-first

* **Room — единственный источник состояния экранов.** ViewModel подписаны на `Flow` из Room; сеть только пишет в Room.
* **Каталог и пагинация.** У каждой строки списка хранится позиция в серверном списке (`catalogIndex`). Смещение следующей
  страницы = длина непрерывно загруженного начала каталога, а не максимальный id: покемон #500, найденный через поиск,
  не сдвигает пагинацию. При очистке кэша у оставленных покемонов позиция сбрасывается, и каталог снова начинается с 0.
  «Загрузить ещё» вычисляется из Room и общего числа покемонов на сервере, поэтому после очистки кэша кнопка возвращается.
* **Фильтр по типу.** Фильтрация идёт по таблице `pokemon_types`, которая заполняется из деталей и из `GET type/{name}`.
  При выборе типа его список скачивается (если старше TTL), так что фильтр работает и на кэше без деталей.
  Без сети показываются сохранённые покемоны этого типа и предупреждение, что список может быть неполным.
* **Поиск.** Одна нормализация запроса для Room и сервера: `#025`, `025` и `25` — одно и то же; `Mr Mime` → `mr-mime`.
  Если точного совпадения нет в кэше — запрос на сервер (`flatMapLatest` отменяет устаревший), найденный покемон кэшируется.
* **Детали.** `CachePolicy` → `FRESH` (без сети), `STALE` (показываем сразу и обновляем, помечаем «устарели»),
  `MISSING` (только сеть, иначе Error + Retry). Детали сохраняются column-level запросами и не затирают позицию в каталоге.
* **Картинки.** Один `ImageLoader` (Coil) на всё приложение: дисковый кэш в `filesDir` (система его не чистит),
  HTTP-заголовки кэширования игнорируются. Предзагрузка кладёт спрайт и арт в тот же кэш, из которого читает UI,
  поэтому после скачивания картинки показываются без сети.
* **Сеть.** `ConnectivityObserver` считает сеть рабочей только при `NET_CAPABILITY_INTERNET` **и** `NET_CAPABILITY_VALIDATED`
  (Wi-Fi без интернета или с captive portal — не онлайн). При восстановлении сети после ошибки — авто-retry.
* **Без сети** доступны: каталог, загруженные детали и картинки, списки типов, коллекции, статусы, заметки, история, фильтры, настройки.

### Фоновая обработка (WorkManager)

| Worker | Когда | Что делает |
|---|---|---|
| `SyncWorker` | периодически каждые 12 ч, если включено; ограничения: сеть (или только Wi-Fi), заряд не низкий | обновляет первую страницу каталога, устаревшие детали и недостающие картинки всех покемонов из коллекций/статусов |
| `PrefetchWorker` | по кнопке «Скачать сейчас» | скачивает первые N покемонов: список, детали, картинки; прогресс в UI через `setProgress` |

* **Ошибки не теряются.** Если не обновился список, хоть одна деталь или картинка — воркер возвращает `retry`
  (экспоненциальная задержка), после последней попытки — `failure` с числом ошибок. Повтор дешёвый: свежие детали
  и уже скачанные картинки пропускаются, каждый покемон сохраняется сразу после загрузки.
* **«Последняя полная синхронизация»** записывается только если ничего не упало; неудачная попытка сохраняется отдельно
  и показывается в настройках («обновила не всё, будет повтор»).
* **Параллельность.** Запросы выполняются параллельно, не больше 8 одновременно (`Semaphore`), — 386 покемонов
  не упираются в лимит времени работы воркера; прерванная задача продолжает с места остановки.
* **Повторный запуск предзагрузки.** Тот же объём и правило сети — текущая задача сохраняется; другой объём —
  задача заменяется (`REPLACE`), уже скачанное не теряется. Интерфейс сообщает, что именно произошло.
* `SyncScheduler` подписан на настройки и перепланирует (`ExistingPeriodicWorkPolicy.UPDATE`) или отменяет
  периодическую работу; воркеры создаются через `HiltWorkerFactory`; логика — в `SyncEngine`, тестируется отдельно.

### Flow-композиция

`PokedexViewModel.uiState` = `combine` из: запроса (`debounce → normalize → distinctUntilChanged`), чипов фильтра,
активного профиля (`flatMapLatest`), списка из Room, статусов профиля, сохранённых фильтров, удалённого поиска
(`flatMapLatest` с отменой), загрузки списка типа (`merge` выбора типа и refresh → `flatMapLatest`),
состояния каталога из Room (`canLoadMore`), состояния сети, потока refresh/retry (`MutableSharedFlow` + `collectLatest`),
подключения к сети (авто-retry через `drop(1).filter`), настроек профиля (сортировка по умолчанию).
`StateFlow` — состояние, `Channel` — одноразовые сообщения (snackbar), `SharedFlow` — поток действий.

  поиск `#025` находит покемона в кэше без запроса на сервер; `#007` ищется на сервере как `7`;
  кнопка «Загрузить ещё» следует за состоянием каталога (в т. ч. после очистки кэша);

**Интеграционные (Robolectric + Room in-memory + fake API) (35)**

  количеством сохраняет задачу, с другим — заменяет**; неполная предзагрузка повторяется WorkManager'ом и завершается успехом.
