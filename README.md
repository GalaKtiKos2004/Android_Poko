# PokeVault — финальный проект

**ФИО:** Ковтун Кирилл
**Группа:** _Б9123-09.03ю03 пикд(2)_

Персональный offline-first «покедекс» поверх [PokeAPI](https://pokeapi.co/) (без ключа).
API — источник контента (список и детали покемонов), а ценность приложения — в локальной модели:
профили, коллекции, статусы, заметки, история, сохранённые фильтры, политика актуальности кэша и фоновая синхронизация.

## Что добавлено в финальной работе

| Было (ДЗ 6) | Стало |
|---|---|
| Список + деталка из API, избранное | Локальные **профили**, у каждого — свои коллекции, статусы, заметки, история, фильтры и настройки |
| Room как кэш/избранное | Room — единый источник истины для UI; 7 таблиц со связями и каскадным удалением |
| Ручной refresh | **TTL-политика** актуальности, офлайн-предзагрузка и **периодическая синхронизация** через WorkManager |
| Flow для поиска | Экран собирается из 7+ независимых потоков (ввод, фильтры, профиль, Room, удалённый поиск, сеть, действия пользователя) |

### Новые пользовательские данные (Room)

| Таблица | Что хранит | Связи |
|---|---|---|
| `profiles` | локальные профили (имя уникально) | — |
| `collections` | пользовательские коллекции (название, описание) | FK → profiles, CASCADE; имя уникально в рамках профиля |
| `collection_pokemon` | состав коллекции + заметка к покемону внутри коллекции | many-to-many, FK → collections, CASCADE |
| `user_pokemon` | статус «Хочу / Поймал» и личная заметка | FK → profiles, CASCADE |
| `history` | история просмотров: одна строка на покемона, время и счётчик | FK → profiles, CASCADE |
| `filter_presets` | сохранённые фильтры (запрос, тип, статус, сортировка) | FK → profiles, CASCADE |
| `pokemon` | кэш контента API + метки `listUpdatedAt` / `detailUpdatedAt` для TTL | не связан FK, чтобы очистка кэша не задевала пользовательские данные |

**DataStore** хранит только настройки: активный профиль, TTL кэша, фоновую синхронизацию, «только Wi-Fi»,
объём предзагрузки, время последней синхронизации, а также настройки профиля (тема, сортировка по умолчанию,
запись истории) с ключами вида `p{id}_theme`.

### Новые сценарии

1. **Локальные профили (крупный).** Создание / выбор / удаление профиля. Активный профиль хранится в DataStore и
   восстанавливается после перезапуска. Все личные данные и настройки разделены; при переключении профиля
   все экраны перестраиваются через `flatMapLatest`, меняется даже тема. Удаление профиля каскадно удаляет его данные.
2. **Пользовательские коллекции (крупный, новая сущность и связь).** Создание, переименование, удаление коллекций
   с валидацией имени; добавление покемона из деталки (в том числе «создать и добавить»), без дублей;
   экран коллекции со своими заметками к каждому покемону. Обложка и счётчик — из SQL-запроса.
3. **Статусы и заметки.** «Хочу / Поймал» + личная заметка на деталке. Статусы влияют на список (бейджи и фильтр
   через `LEFT JOIN` в запросе Room) и на статистику профиля в настройках.
4. **Сохранённые фильтры.** Текущий запрос + тип + статус + сортировка сохраняются под именем и применяются одним
   нажатием; управление (удаление) прямо на экране списка.
5. **Офлайн-режим и актуальность данных.** TTL (1/6/24/72 ч), кнопка «Скачать сейчас» для первых 151/251/386
   покемонов с прогрессом, периодическая синхронизация, очистка кэша с сохранением всего, что нужно пользователю.
6. **История / recent.** Последние просмотры с количеством просмотров, удаление записи, очистка; запись можно
   отключить в настройках профиля («инкогнито»).

### Как устроен offline-first

* **Room — единственный источник состояния экранов.** ViewModel подписаны на `Flow` из Room; сеть только пишет в Room.
* **Список:** при открытии показывается кэш; первая страница перезапрашивается, только если кэш пуст или старше TTL.
  Ошибка сети при наличии данных показывается баннером, а не экраном ошибки. «Загрузить ещё» — пагинация в Room.
* **Детали:** `CachePolicy` → `FRESH` (без сети), `STALE` (показываем сразу и обновляем в фоне, помечаем «устарели»),
  `MISSING` (только сеть, иначе Error + Retry). Обновление списка не стирает уже загруженные детали.
* **Поиск:** локальный поиск по Room работает без сети; если точного совпадения нет — запрос на сервер
  (`flatMapLatest` отменяет устаревший запрос), найденный покемон кэшируется.
* **Сеть:** `ConnectivityObserver` (callbackFlow) → офлайн-баннер; при восстановлении сети после ошибки — авто-retry.
* **Без сети** доступны: весь кэш списка, все загруженные детали, коллекции, статусы, заметки, история, фильтры, настройки.

### Фоновая обработка (WorkManager)

| Worker | Когда | Что делает |
|---|---|---|
| `SyncWorker` | периодически каждые 12 ч, если включено в настройках; ограничения: сеть (или только Wi-Fi), заряд не низкий | обновляет первую страницу списка и **устаревшие детали всех покемонов, которые есть у пользователей в коллекциях/статусах**; записывает время синхронизации; `retry` с экспоненциальной задержкой при ошибке |
| `PrefetchWorker` | по кнопке «Скачать сейчас» (unique work, KEEP) | предзагружает список и детали первых N покемонов для офлайна, пропуская свежие; отдаёт прогресс в UI через `setProgress` |

Логика вынесена в `SyncEngine` (тестируется отдельно); `SyncScheduler` подписан на настройки и
перепланирует/отменяет периодическую работу при их изменении (`ExistingPeriodicWorkPolicy.UPDATE`).
Воркеры создаются через `HiltWorkerFactory`.

### Flow-композиция (из ДЗ 6, развитая)

`PokedexViewModel.uiState` = `combine` из: запроса (`debounce → map → distinctUntilChanged`), чипов фильтра,
активного профиля (`flatMapLatest`), списка из Room, статусов профиля, сохранённых фильтров, удалённого поиска
(`flatMapLatest` с отменой), состояния сети, потока действий refresh/retry (`MutableSharedFlow` + `collectLatest`),
подключения к сети (авто-retry через `drop(1).filter`), настроек профиля (сортировка по умолчанию).
`StateFlow` — для состояния, `Channel` — для одноразовых сообщений (snackbar), `SharedFlow` — для потока действий.

## Тесты

Всего **47 тестов**: 27 unit + 20 интеграционных/UI. Все детерминированные (виртуальное время, фейки, in-memory Room).

**Unit (бизнес-логика и ViewModel)**
* `CachePolicyTest` — FRESH/STALE/MISSING, граница TTL, принудительное обновление.
* `NameValidatorTest` — нормализация, пустое/длинное имя, дубли без учёта регистра.
* `MappersTest` — id из URL, порядок типов, сохранение `listUpdatedAt`, битые данные, неизвестные enum в пресетах.
* `PokedexReducerTest` — кэш побеждает ошибку сети; пустой результат = `Empty`, а не `Success(emptyList())`.
* `PokedexViewModelTest` — начальное состояние; **полная последовательность** Loading → Error → Loading → Success при retry;
  debounce (один запрос на серию нажатий); **отмена устаревшего удалённого поиска** и недопуск его результата в UI;
  авто-retry при появлении сети; переключение профиля меняет список и бейджи; сообщение о сохранении фильтра
  приходит один раз и не попадает в state; применение пресета восстанавливает фильтр.
* `DetailViewModelTest` — id из `SavedStateHandle`; офлайн с кэшем = данные + пометка «устарели», а не Error;
  Error → Retry → Success; повторное нажатие статуса снимает его; история не пишется, если выключена;
  «создать коллекцию и добавить».

**Интеграционные (Robolectric + Room in-memory)**
* `OfflineFirstRepositoryTest` (Repository + Fake API + Room) — данные переживают отключение сети; TTL списка и деталей;
  обновление списка не стирает детали; 404 → null, найденный покемон кэшируется; очистка кэша сохраняет используемое.
* `UserDataIntegrationTest` — изоляция данных профилей; каскадное удаление профиля и завершение сессии;
  нет дублей в коллекции; история — одна строка на покемона, порядок и счётчик; уникальность имён в рамках профиля;
  статус + заметка, пустая запись удаляется.
* `SyncTest` (SyncEngine/Workers + Fake API + Room) — предзагрузка с прогрессом и частичными ошибками;
  свежие детали не качаются повторно; фоновое обновление трогает только устаревших покемонов пользователей;
  время синхронизации пишется только при успехе; `SyncWorker` success/retry/failure; `PrefetchWorker` с параметром.
* `PokedexUiTest` (Compose UI) — Retry на экране ошибки; клик по элементу списка → переход на деталку с нужным id;
  ViewModel + экран: ошибка → Retry → список на экране.
